# 剧本资产提取

本技能负责“从已经写成的剧本中提取资产”，不是提前凭空设计美术。输入优先级为：完整文学剧本 > 已锁定大纲/分集表 > 人物正典、时间线、连续性和已有资产版本库。**只有完成正文并与大纲交叉核对后，才把提取结果标记为完整；大纲阶段的资产只能标 `planned`。**

## 触发与边界

- 适用于用户要求资产提取、角色立绘清单、场景库、道具库、视觉变体、AI生成提示词或制作前资产盘点。
- 默认覆盖人物、人物视觉变体、地点本体、地点场景变体、可复用道具及道具状态变体。
- **只出现在一个不同场号的可见道具均不建长期P本体；仍保留在逐场一次性道具表。**即使承担线索、身份、规则或镜头连续性功能，也先记为场次局部道具；只有正文在第二个不同场号实际复用后才重新评估晋级。
- 被对白、旁白或大纲提到但没有可见呈现的对象，标记 `mention_only`，不生成画面资产，不把推断当成正文事实。
- 不修改正文、不擅自补写剧情；缺少全文时输出覆盖范围、待核查项和计划记录。

## 核心数据模型

稳定本体编号沿用项目协议：人物 `C01`，地点 `L01`，道具 `P01`；剧情视觉变体分别为 `C01-V01`、`L01-V01`、`P01-V01`；制作文字或素材修订为 `@r001`。资产提取表的行号不是故事先后，首次出场、复用集场和故事时间另列。

每条记录至少包含：

- `asset_id`、规范名称、别名/代称及归并依据；
- `visibility`: `on_screen`（正文实际可见）、`visible_reference`（画面需要指向但不独立生成）或 `mention_only`（只被提及）。导入制作表时分别映射为 `visible`、`visible_reference`、`mention_only`；
- `reuse_class`: `reusable_asset`、`narrative_singleton_candidate`、`one_off_scene_prop`、`not_asset`；
- `asset_decision`: `promote`、`scene_only`、`index_only`、`pending`；仅 `promote` 写入长期 C/L/P 版本库；
- `occurrence_scene_count`: 按**不同场号**计数，场内重复镜头不重复计数；
- `first_scene`、`used_scenes`、故事时间/叙事层和正文证据；
- `canon_description`: 严格依据正典和正文的事实描述；
- `visual_prompt_safe`：仅本体使用的完整视觉提示词，必须足以在没有变体信息时独立生成该人物、场景或道具；不含人名、剧情推断、未证实属性或不可见心理；导入制作版本库时映射为 `safe_prompt`；
- `visual_prompt_delta`：仅变体使用的差量提示词，只描述相对继承本体（或上一明确变体）发生的视觉变化，不重复未改变的字段；
- `prompt_inheritance`：变体继承来源、覆盖字段和展开规则。制作或生成前按 `base_prompt + inherited_variants + visual_prompt_delta + optional_style` 临时展开为 `resolved_prompt`；
- `style_profile` / `style_directive`：项目级可选风格设定及本条资产是否继承。项目没有设定风格时填 `none`，不凭空补写风格词；
- `status`: `planned`、`drafted`、`reviewed`、`revised`、`delivered`。

## 执行流程

### 1. 读取输入并登记覆盖范围

记录剧本文件、集数、已完成场次、是否有分集大纲、人物/世界规则/时间线版本和缺失附件。以场号为最小证据单位；同一人物的“我、他、老板、母亲”等称呼先建立别名候选，不能仅凭相似词强行合并。

### 2. 先建立归并台账

逐场扫描人物、地点、可见物件和状态词，建立 `alias_map`。别名合并需要至少两项一致证据（同一身份、同一持续特征、同一关系或明确代称回指）；证据不足时保留 `C/L/P?` 候选并列入 `open_issues`。复制品、假货、同款另一件、不同实体的同名物件必须分设本体并记录关联。

### 3. 提取人物本体与人物视觉变体

人物本体保存身份锚点：姓名/称呼、功能、脸部与体态识别点、年龄阶段、声线和持续特征。人物视觉变体按**任何观众可见且会影响生成或连续性的明显变化**拆分，包括：

- 年龄/时代/现实与回忆层；
- 日常、工作、礼服/舞会、制服、伪装等服装组合；
- 发型、妆容、发饰、首饰、鞋包变化；
- 湿润、沾尘、衣褶破损、疲惫、绷带、伤痕、污渍等持续状态；
- 影响身份辨识、动作或线索的佩戴/缺失状态。

仅有瞬时表情、普通抬手或不影响连续性的动作不建V；写入场次动作即可。每个V必须列出继承来源、覆盖字段和 `visual_prompt_delta`；变体提示词只写改变的地方，不用“同上”代替字段，也不重复本体完整提示词。生成或交付镜头时才将本体完整提示词与变体差量合并为临时 `resolved_prompt`。关键发饰、首饰或衣物若独立持有、掉落、赠送、调包或承担证物功能，同时建P并与C变体双向引用。

### 4. 提取场景本体、层级与场景变体

按空间而非镜头建立地点本体。固定建筑、房间比例、门窗、出入口、相邻区域和行动路线属于L本体；同一空间的昼夜、天气、季节、活动布置、光线、损坏/清理/重建、时代层和可见通路变化属于L-V。

场景必须建立 `parent/child` 层级：主场景（如某宅院、医院、工地）只登记一次，实际进入且需独立视觉生成的大厅、卧室、走廊、后门等登记为子场景，并引用同一父L的 `style_base`。不同建筑或空间关系已经改变时新建L，不用V掩盖换地点。不同机位不自动新建场景。`style_base` 只有项目或用户已设定时才填写；未设定时写 `none`，不擅自添加风格描述。

### 5. 提取道具本体、道具变体和一次性道具

道具本体保存实物身份、尺寸比例、材质、颜色、独有标记和用途边界。明显可见状态变化建P-V，例如完好/打开/封存/破损/修复/沾尘/湿润/通电/熄灭、内容或可读文字变化、母件拆分和真假替换。所有权、持有人和位置单独记录，不因换手自动新建V；同款另一件、复制品、伪造件或碎片成为独立P并建立母子关联。

先按不同场号统计出现次数，并将本技能字段映射到制作版本模板：`visibility`→`appearance_mode`，本体 `visual_prompt_safe`→`safe_prompt`，变体 `visual_prompt_delta`→`prompt_delta`，`asset_decision`保持同名。

- `occurrence_scene_count >= 2`：进入可复用P资产库；
- 只在一个场号出现：严格不进长期P资产库，标 `one_off_scene_prop`；若承担线索、身份、规则或回收作用，再加 `narrative_singleton_candidate` 标记，但 `asset_decision` 仍为 `scene_only`，放入该场的逐场道具表；只有正文后来出现第二个不同场号，重新提取并记录晋级依据后才可转为P本体；
- 仅被提及：`mention_only`，只留引用，不生成P提示词。

判断“关键功能”仍需附正文证据，但关键功能不会覆盖“一次性不入库”规则；不能为了凑资产数量把普通杯子、纸巾、一次性包装等提升为P本体。

### 6. 生成正典描述与分层提示词

每项资产都分开写：

1. **canon_description**：可被正文、连续性、伏笔和制作审查引用的事实；不把模型推测写成确定事实，未知项标 `待核`。
2. **本体 `visual_prompt_safe`**：纯视觉可执行的完整文本。人物写年龄阶段、五官/发型、服装、妆发、配饰、体态和稳定识别点；场景写建筑/空间、布局、时间天气、光线、色调、材质和氛围；道具写形状、材质、纹理、状态、尺寸感和可读标记。不得加入人名、对白、剧情因果、内心情绪、不可见关系、未确认品牌或正文没有的细节。
3. **变体 `visual_prompt_delta`**：仅写相对继承来源变化的可见字段，例如“改为深蓝丝绒礼服，发髻改为低盘发，右侧增加银色发簪”；没有变化的字段不重复。若变体是首个可生成状态，仍先建立本体完整提示词，不得用变体差量代替本体。
4. **风格字段**：只有 `style_profile` 中已有项目级或用户明确指定的风格才可并入提示词；未设定时 `style_directive=none`。风格不是变体差量的默认内容。

若项目已有视觉提示词约定，沿用其风格；不能为满足提示词而改变canon。人物和道具的提示词不默认带手持物或动作，实际持有、位置和镜头动作写在逐场/镜头绑定中。提交制作层时使用 `resolved_prompt` 临时展开：本体完整提示词 + 按顺序继承的变体差量 + 已锁定的可选风格；不得把展开结果反写成变体原文。

### 7. 与正文和资产版本库对照

把可复用结果合并到项目 `production/资产版本库.md`；把每场的C/L/P变体、进出状态、一次性道具和状态转换写入 `production/逐场资产绑定.md` 或镜头表。不得覆盖旧版本；已有编号、姓名、场景和道具优先复用，冲突列 `canon_delta` 和影响范围。

### 8. 验收和交付

逐场检查：人物是否漏提、同一人是否被重复建档、场景父子关系是否稳定、道具是否有持有人/位置/状态交接、变体是否有正文依据、一次性道具是否错误进入资产库、`mention_only` 是否误生成画面资产。最后输出 `evidence`、`canon_delta`、`open_issues`、`next_stage_inputs`，并声明覆盖率与未读范围。

## 默认交付

主文件：`production/资产提取清单.md`。模板见 [资产提取清单模板](assets/asset-extraction-template.md)，判定细则见 [提取判定与归并规则](references/extraction-rules.md)。

主文件至少包含：

1. 输入与覆盖范围；
2. 资产索引与统计（C/L/P、V数量、场次计数、on_screen/mention_only、一次性道具数）；
3. 人物本体表与人物变体表；
4. 主场景/子场景表与场景变体表；
5. 可复用道具本体表与道具变体表；
6. 逐场一次性道具及未入库可见物表；
7. 别名归并、待核对项和命名冲突；
8. `evidence`、`canon_delta`、`open_issues`、`next_stage_inputs`。

若用户要求AI绘图，提示词仍必须从本清单派生，并在实际生成后另记 `@r` 修订和验证状态；文字提取不等于素材生成通过。
