# 资产提取判定与归并规则

## 1. 资产资格矩阵

| 情况 | visibility | reuse_class | 长期资产库 | 逐场表 | 需要提示词 |
|---|---|---|---|---|---|
| 人物在正文中实际出现 | on_screen | reusable_asset | C本体及必要C-V | 是 | 是 |
| 场景实际进入且有画面 | on_screen | reusable_asset | L本体及必要L-V | 是 | 是 |
| 道具出现在两个以上不同场号 | on_screen | reusable_asset | P本体及必要P-V | 是 | 是 |
| 道具只在一个场号出现且无关键功能 | on_screen | one_off_scene_prop | 否 | 是 | 可选，写场景局部描述 |
| 物件只在对白/旁白/大纲提及 | mention_only | not_asset | 否 | 只留引用 | 否 |
| 关键线索或身份物件只出现一次 | on_screen | narrative_singleton_candidate | 否（严格不入长期P库） | 是，逐场保留 | 可选，按场景描述 |

关键功能包括：改变人物识别、证明事实、触发规则、承接伏笔、发生交接、需要跨镜头保持外观、在后续回收或被对照。关键功能必须附正文位置，但不覆盖“一次性道具不成为长期资产”规则；这类物件标 `narrative_singleton_candidate`，只有正文在第二个不同场号实际复用后才重新评估晋级为P本体。

## 2. 出现次数口径

`occurrence_scene_count` 统计不同 `EPxxx-Sxx`，不是台词次数、镜头次数或段落次数。一个场中出现十次仍记1；回忆中的同一物件按不同叙事层和场号另列证据，但不自动变成不同实体。使用场景别名归并后再统计。

## 3. 别名合并

### 可直接合并

- 明确同一姓名的简称、昵称、职务称呼；
- 同一地点的“店里/后厨/收银台”在空间层级上有明确父子关系；
- 同一物件的材质、独有标记、持有链和后续回收一致。

### 必须暂缓

- 只有颜色或功能相似，没有身份/持有链证据；
- “钥匙”“那份合同”等泛称可能指多个实物；
- 真假件、复制件、同款另一件、梦境/回忆中的不可靠物件；
- 文本使用第一人称或代称但没有可靠回指。

暂缓项编号加 `?` 或进入待核表，不把猜测写入canon。补证据后再合并，并记录受影响的场次和提示词。

## 4. 人物变体判定

建立C-V的门槛是视觉、制作或连续性可观察变化。下列任一项命中即可拆分：年龄/时期、现实与回忆层、明显换装、礼服或制服、发型/妆容/发饰、持续伤痕或绷带、湿润/沾尘/破损、身份伪装、关键配饰增减。普通表情、一次性姿势、镜头景别和短暂抬手不拆。

变体卡必须展开继承后完整状态：服装、鞋包、妆容、发型、发饰、首饰、身体状态、声音/动作限制。若C-V引用关键P，双向链接佩戴位置、取下或交接场次。

## 5. 场景层级与变体

- L本体回答“这是哪一处空间”：结构、比例、固定出入口和邻接关系。
- L-V回答“这处空间现在呈现什么状态”：昼夜、天气、季节、活动布置、灯光、损坏、清理、修复、历史时期。
- 机位、景别、镜头方向不单独建L或L-V。
- 同一建筑内实际进入的大厅、卧室、楼梯、后门等为子场景；只在对白提及、没有进入画面的房间标 `mention_only`。
- 通路、遮挡或目击条件改变且影响因果时，即使外观相近，也要建独立L-V并连接T/N/F。

## 6. 道具状态与归属

物理外观变化建P-V；所有权、当前持有人、位置变化只写在绑定/转换记录，除非物件本身也发生可见变化。开合、封缄、内容、完整度、湿污、通电、屏幕文字、刻痕、缺口、真假替换均可能成为V。碎片在独立交换或成为证据时建新P并关联母件，数量守恒。

## 7. 描述分层与提示词继承

`canon_description` 只写文本有证据的事实，可带“待核”。

### 本体提示词

人物、场景、可复用道具本体必须填写一条可独立使用的完整 `visual_prompt_safe`：

- 人物：年龄阶段、五官/肤色、发型发色、服装层次、妆容、发饰/首饰、鞋包、体态和稳定识别点；
- 场景：建筑/空间结构、固定布局、出入口、材质、时间和可见光线；若项目设定了风格，再加入 `style_profile`；
- 道具：形状、比例、材质、颜色、纹理、独有标记、基础物理状态和可读标记。

不得放人名、对白、剧情因果、心理、未证实品牌或正文没有的细节。若正文只说“一个包”，提示词不要擅自写皮革、品牌或颜色；可以写“待补：材质、颜色”。

### 变体差量提示词

变体不重复本体完整提示词。每条变体必须记录：

1. `prompt_inheritance`：继承的本体或上一明确变体ID；
2. `override_fields`：实际覆盖的字段；
3. `visual_prompt_delta`：只描述改变的视觉内容，例如“礼服改为墨绿色丝绒，发型改为低盘发，左耳增加珍珠耳坠”；
4. `style_directive`：仅在项目已有风格或用户明确指定时填写，否则为 `none`；
5. `resolved_prompt`：只在分镜/生成/交付前按继承链临时展开，不把展开后的整段文字回写到变体字段。

变体没有改变的五官、空间骨架、材质等字段不重复；“同上”不能代替继承来源和覆盖字段。若本体字段缺失，先补本体，不得用差量提示词掩盖本体不完整。

### 风格设定

风格是项目级可选字段。项目或用户没有锁定风格时，`style_profile=none`、`style_directive=none`，不自行补写“电影感、赛博、国风、写实”等词。风格可以在后续制作阶段加入，但必须记录来源和影响范围，不能修改 `canon_description`。

### 提示词展开

制作层读取 `base_prompt`（本体完整提示词），沿变体继承链按时间顺序合并 `visual_prompt_delta`，最后追加已锁定的可选风格，生成临时 `resolved_prompt`。本体和差量仍分别保存，便于跨镜头复用、回溯和改稿。

## 8. 完整性门槛

只有当所有已完成正文场次都有扫描记录，人物/场景/可见道具的归并已复核，且逐场表能追踪版本进出状态时，资产提取范围才标 `reviewed`。未读集数、缺失大纲、无法确认的身份和只在大纲中的计划均列入覆盖缺口，不用“完整资产库”表述。
