# 项目协议与跨技能数据

这是整套技能的共享约定。管理字段放在正文之外，人物对白保持自然。

## 用户要求与默认值

优先级：用户当次明确约束 > 本项目已确认事实 > 本包默认 > 通用经验。新要求与旧事实冲突时列出影响并修订，保持其余事实稳定。

| 项目 | 初始值与处理 |
|---|---|
| 题材 | 多题材通用，按当前项目选择；都市反差喜剧＋系统爽剧作为可选专项 |
| 形式 | AI 竖屏短剧，中文；按用户指定切换真人、横屏、纯音频 |
| 正文 | 人物对白＋内心独白/心声＋必要旁白/系统音；配简洁场次与必要动作提示 |
| 单集时长 | 每季前三集各120—180秒，后续各60—90秒；每季上限8400秒（140分钟）。默认每季前三集150秒、后续65秒，总8055秒（134分15秒） |
| 总集数 | 默认每季120集；`season_count` 可由用户手动输入。每季有独立集数与时长预算，系列累计时长不再套用单季140分钟上限 |
| 前三集字数 | 初稿每集约 900 字、合计约 2700 字；含动作与标点，发声字数另计 |
| 前三集场景 | 单集最多 3 个有叙事作用的场景作为默认预算 |
| 核心人物 | 单集优先 2—3 人，默认上限 4 人；背景人群单列 |
| 有效节拍 | 前三集每集至少 3 个状态变化，常用 3—5 个 |
| 开篇模式 | 结果前置型／冲突开场型／信息差开场型；保留能力触发、误会、反常动作、关系失衡、机会/证据倒计时等路径，依题材选择 |
| 评分 | 内部修订工具，附正文证据；不转换成市场保证 |

默认数值是创作预算。用户要求硬执行时写入 `hard_constraints`；因剧情调整时在 `deviations` 写明理由、影响与承接的戏剧功能。正常可逆创作决定直接推进。

## 第一集钩子字段

`primary_hook_mode` 用 `result_preposition`（结果前置型）、`conflict_opening`（冲突开场型）、`information_gap`（信息差开场型），或已说明理由的其他机制；`secondary_hook_modifier` 可为空或取 `ability_trigger`、`misunderstanding`、`abnormal_action`、`relation_imbalance`、`countdown_evidence` 之一。`hook_selection_log` 留存候选、选择依据与状态。正文、审稿和续写沿用同一选择，换类时记录影响。

## 稳定标识

人物 `C01`；地点 `L01`；道具 `P01`；规则 `R01`；伏笔 `F01`；承诺 `PR01`；集号 `EP001`；场号 `EP001-S01`；节拍 `EP001-B01`；镜头 `EP001-S01-SH01`。昵称映射同一人物 ID。多季项目另存季号和全局 ID：`S01-EP001`、`S01-EP001-S01`、`S01-EP001-B01`；旧的 `EP001` 视为 S01 本地编号，不得在 S02 覆盖。

主线 `M01`、支线 `B01`、事件节点 `N001`、图边 `G001`。所有分集至少对应一个改变局面的事件节点；图的事实与正文共用canon，不另建相互冲突的剧情版本。

资产变体 `C01-V01`、`L01-V01`、`P01-V01`；多季新增变体优先写 `S02-C01-V01`，完全复用时保留原 ID 并记录来源季；制作修订引用 `C01-V01@r001`；状态转换 `T001`。C/L/P表示本体，V表示剧情所需状态，r表示该状态的一次文字设计或素材修正，T表示一次转换或已标明的叙事切换。编号登记顺序与故事发生顺序分别记录。

## 人物命名接口

人物姓名不是模型随手填入的装饰字段。用户明确提供的姓名属于已确认事实，除非用户要求改名，不擅自替换；用户未提供姓名、要求重新命名或触发命名审查时，必须读取 [命名设计规则](../../drama-characters/references/name-design.md)，为男女主及主要角色重新建立候选、选择依据和冲突核对。不得直接套用高频都市姓名、古偶常用姓名、网文默认姓氏组合或当前模型第一反应。

- 命名要同时考虑题材/时代、阶层职业、人物欲望与缺陷、声音辨识、字形画面和关系称呼。男主、女主、主要对手在姓氏、声调、字形和称谓上应明显可区分；“生僻”不等于难读，必须做口播与误听检查。
- 输出至少包含 `name_id`、正式姓名、读音/重音、别名/称谓、命名意图、人物特征映射、避用或淘汰候选、项目内相似度核对、用户确认或采用状态。姓名可有隐喻，但剧情不必靠解释姓名才成立。
- 设计阶段的候选标 `planned`，正文采用后标 `canon`；改名必须登记旧名→新名、原因、受影响集场、对白、字幕、资产提示词和伏笔，并全文搜索旧称谓。
- “不大众化”是项目内和候选集中的差异目标，不声称全球唯一；若姓名含方言、时代或跨文化读音风险，标注试读项。没有实际语料库时如实记录采用的本地核对范围。

## 开篇与动作接口

人物个性使用 [性格行动化规则](../../drama-characters/references/personality-in-action.md)：`02-characters.md` 保存性格行为卡，`canon/characters.md` 保存当前有效规则、阶段变化与卡片索引。写场次时读取触发点、目标、知情范围、关系对象、惯用策略与代价；按“性格倾向→动作/对白/心声→回应→后果”留下集场证据。稳定倾向、暂时情绪、伪装与成长分别管理，后续集及续季沿用已有发展。管理信息放在备注和审稿表，正文自然呈现。

前三秒默认先给发生中的可见/可听事件，不先念姓名、年龄、世界史或能力说明。可选择系统/技能触发、结果前置、非血腥危险、反常动作、身份误会、关系失衡或物件异常；第一帧要让观众能提出一个具体问题。系统或技能必须在行动中显示一次有效作用，同时露出一条限制、代价、冷却或适用条件，不把“觉醒”当作解释段。

误会钩子必须有真实指向物、合理视线和尽快可验证的澄清；例如人物说“好大”，镜头让观众先误读为在看女生，随后通过他的手、视线或下一句明确是在说女生旁边的巨大物件。误会改变当场行动或关系才成立，不能靠低俗凝视或拖延澄清。

动作细节按“刺激→身体先反应→人物压住/伪装→有目的的微动作→物件/空间结果→对白或停顿”组织。每个细节至少服务人物状态、真实情境、信息/伏笔、关系或资产连续性之一；删去只为漂亮的随机小动作。背景和世界规则后置到它们影响当前选择时再释放。

## 资产版本接口

按 [资产提取技能](../../drama-asset-extraction/SKILL.md)、[资产版本规则](../../drama-ai-production/references/asset-versions.md) 与 [资产模板](../../drama-ai-production/assets/asset-version-tables.md) 管理四份资产文件。最终提取必须在完整剧本和完整分集大纲都齐后执行；完整正文是主要事实来源，大纲用于补充阶段和未来变体；先交付 `production/资产提取清单.md`，再把 `promote` 条目写入版本库。所有只出现在一个不同场号的道具标为 `scene_local_one_off`，即使承担线索、身份或回收作用也不进入长期P资产库，必须保留在逐场资产绑定；仅被对白、心声或旁白提及的物件标为 `mention_only`，只进入索引，不生成视觉提示词。后来在第二个不同场号出现时，重新提取并登记晋级依据。

- 人物、场景和道具均区分 `canon_description`（正典事实）与工具提示词。本体的完整 `visual_prompt_safe` 导入制作版本库映射为完整 `safe_prompt`；变体仅保存继承来源、覆盖字段与 `visual_prompt_delta`，导入后映射为 `prompt_delta`。仅在镜头生成时展开 `resolved_prompt`，不写回变体。项目未明确设定风格时，提示词不添加风格描述。提示词不能反向改变人物身份、场景路线、道具归属或线索特征。
- 道具按不同场次统计出现次数；至少出现在2个不同场次且具有复用、连续性或叙事价值才晋级P本体。一次性道具即使承担线索、身份或回收作用，也不得仅凭功能晋级；后续在第二个不同场号实际出现后，须更新提取清单并记录晋级依据。
- 同一建筑内改变房间、出入口或行动路线时建立新L本体；同一空间仅昼夜、天气、布置、损坏或修复变化时沿用L并建立L-V变体。

- 人物变体覆盖时期年龄、服装鞋包、妆容、发型、发饰首饰、身体状态与声音变化；同一身份锚点跨版本保留。剧情关键发饰独立建P编号并关联佩戴部位与持有人。
- 场景保留固定布局，按昼夜、天气、布置、时期、破坏和修复建立所需变体；道具的外观内容与归属位置分别记录。
- 逐场绑定记录场号、故事时间/叙事层、呈现顺序、C/L/P具体变体及r号、进出状态、动作边界和T编号。同场有变化时拆段，回忆引用历史状态。制作镜头继承这些绑定。
- 绑定的 `status` 取 `planned`（拟写）或 `written`（已有对应正文）；另记复核结果和制作状态。`written`不表示图像已经生成。
- 资产剧情状态分计划、已落正文、已复核；制作状态分文字设计、已生成参考、静帧已审、运动已审、已交付素材。r001可以仅指文字设计，须写实际类型与文件状态。
- 有关键因果或线索作用的变化连接N/F/M/B；日常换装可只写T及场次依据。使用中的版本有历史引用，改稿或美术修订列出受影响场次和镜头，完成复核后更新。
- 只建立剧情用到的组合，先查现有变体再新建。资产技术字段保存在附件；正文只写有叙事作用的外观与状态变化。

## 逐集资产与全剧分镜接口

资产版本库与逐场绑定确认后，按 [每集资产使用清单模板](../../drama-ai-production/assets/asset-version-tables.md) 汇总每集所有可见的 C/L/P 本体、具体 V/r、使用场次、场内 T 转换及仅出现一次的场次局部道具。清单是分镜引用索引，不因同一资产多次出场而丢失场次；`mention_only` 标记为文字引用，不当作出镜资产。

全剧分镜读取 [分镜规范](../../drama-ai-production/references/storyboard-guide.md) 和 [镜头模板](../../drama-ai-production/assets/shot-table.md)，覆盖全部已完成正文场次。未另定时每镜先按30秒规划，再按真实表演、剪辑和声音需要调整；逐镜记录人物表演逻辑与情境化微动作、场景人物、起止帧景别/站位/状态、机位、运镜、构图、焦段、画面与声音、音效、切点和资产版本。对白镜头以承载可听对白的镜头数为分母，过肩或正反打镜头占比至少65%；关键反应与状态变化给可表演特写。每集及每季核对镜头时长之和与预算、场次覆盖、资产绑定和跨镜连续性。未经实际生成或样片实读的分镜标文字设计，不记为已验证素材。

## 多季承接接口

多季项目读取[多季架构与续写协议](multi-season.md)。启动时让用户填写 `season_count`；若暂未确定，按一季执行并保留系列级开放线，不凭空写后续季正文。每季必须有自己的定位增量、结构、分集、正文、资产附件和审稿状态，`runtime_budget.max_total_seconds` 不得超过 8400 秒。

一季完成后封存 `canon/season-handoffs/Sxx-to-Syy.md`，记录本季已兑现承诺、季末选择与代价、人物知情范围、资源余额、时间间隔、资产状态、未回收伏笔和下一季入口条件。跨季因果边使用 `season_bridge`、`carryover`、`reveal` 或 `consequence`，同时填写 `from_season`、`to_season` 和证据。下一季开写时先核对交接，再设计本季前三集，不重置姓名、关系、规则、道具持有人或上一季伤病；普通开放线和本季悬念分开标记。

季末必须给本季主矛盾一个结果与余波，才可以放置下季钩子。未解决关键问题不得静默迁移成下一季既定事实；交付清单逐季列出 `planned/drafted/reviewed/revised/delivered` 状态。

## 子技能输入

`task_scope`、`project_spec`、`canon_version`、`upstream_artifacts`、`hard_constraints`、`reference_material`、`target_output_paths`。单项任务建立最小足够上下文；假设与用户已定事实分别标记。

## 子技能输出

1. 实际创作产物，填入完整内容。
2. `evidence`：`element_id | judgment | episode_scene | observation | action | verification`。设计阶段用拟落场次并标“计划”，正文完成后换成实际证据。
3. `canon_delta`：`fact_id | before | after | reason | source_scene | affected_artifacts`。无变更写“无”（结构化输出用`[]`）；子代理提案由主控合并。
4. `open_issues`：`id | severity | issue | affected_scope | next_action | status`。解决项附复核位置。
5. `next_stage_inputs`：下一步真正需要的事实与文件。

## 时长、字数、节拍

“450 字/分钟”保留为用户提供的创作经验值。全文字数包含动作、场记、对白，发声字数仅计实际口播，分别统计。

初估：`对白秒数 = 发声字数 / 试读语速 × 60`。语速未知时用可配置区间做敏感度估计。顺序动作和停顿另加；边说边做标重叠，避免重复计时。配音实读或样片优先于估算。

对白、内心独白、心声、旁白和系统音全部计入实际发声量。**按季**预算合计不超过8400秒；默认每季8055秒，剩余345秒供重要情感和高潮调整。多季系列允许累计超过8400秒，但修改单集时长要同步当前季合计并更新系列索引。最后一集也保留结果与余波时间。

节拍是目标、策略、信息、力量、关系、风险之一的可识别变化，写“前状态 → 动作 → 后状态”。剪切或重复辱骂不自动算新节拍。超预算先删重复解释，保护因果和情绪所需时间。

## 开篇、爽点、受众

用户已明确重视人物内心独白与心声。默认正文保留这些声音层，不把内在叙述全部改成外在动作；使用 [心声专项](../../drama-inner-voice/SKILL.md) 管理表达与知情边界。普通内心独白仅对观众可听；他人读心需要项目规则支持。系统音、主观推测、可靠事实分别标记，避免角色凭空获知秘密。

第一集目标：快速可理解、值得关心、形成期待、提供即时回报。背景按当前行动需要释放；必要的字幕、短旁白、规则提示保留并说明作用。

强回报可来自反击、解谜、修复关系、展示能力、喜剧释放、获得尊重、救助或拒绝不合理要求。压抑深度依题材和受众确定。男频女频可作发行标签，具体欲望由项目受众决定；不要把能力、美貌和伴侣数量按性别固化。

## 原创与参考

从参考中提炼机制，重新设计目标、角色组合、规则代价、冲突链和结局。分析笔记可短引文定位，正式剧本使用原创对白。比较设定组合、关键场面顺序、人物关系、标志对白、结局五个维度，识别只换名的复刻。

提供参考材料时进入 [参考结构重构](../../drama-reference-rebuild/SKILL.md)。`mode` 保留交付范围，`workflow_mode` 记录 `reference_rebuild`；配置与状态放在 `project.json.reference_rebuild`，至少包括 `reference_phase`、`reference_read_scope`、`reference_ids`、`candidate_count`（默认6、至少3）、`selected_direction_id`、`deep_read_checklist` 与 `similarity_report`。尚未评分的值用 `null`，未评维度标 `N/A`，与相似度为0分别处理。

额外交付 `reference/01-source-manifest.md`、`reference/02-mechanism-matrix.md`、`reference/03-direction-comparison.md`、`reference/04-originality-report.md` 和 `canon/rebuild-ledger.md`。用户选择方向前不启动长篇正文。分数采用专项技能的唯一量表，分清已评范围、缺失材料和高识别重合证据；前期估计、正文审查与法律结论属于不同口径。

跨AI交接附上 `workflow_mode`、`reference_phase`、选定方向、候选比较文件、参考覆盖范围、评分状态和未处理比对项。新稿续写以新作正典为依据；需要比对时再读取原文的相关证据段，参考事件链不进入续写大纲。

## 状态定义

`planned` 只有设计；`drafted` 有完整正文；`reviewed` 已实质审阅；`revised` 已改并复核；`delivered` 范围完整且文件可读。文学正文、对白版、制作附件分别报告状态。
